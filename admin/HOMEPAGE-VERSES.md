# Homepage Bible verses

The existing Microsoft sign-in and Admin API connection authorize **Bible Verses** (`#verses`). Changes are staged in memory until **Publish changes to Dev** saves the complete schedule. Reload explicitly discards staged changes after confirmation. A stale blob SHA prevents overwrite; reload and reapply edits. No automatic conflict retry occurs.

`_content/homepage-verses.json` uses `schemaVersion: 1` and a `verses` array. Each entry has a unique `id`, plain-text `reference`, `translation`, `quotation`, Monday `startDate`, Sunday `endDate`, boolean `published`, and internal `note`. Optional `createdAt`/`updatedAt` timestamps use UTC ISO format. Drafts can lack wording or a scheduled week. Published entries must be complete. Published weeks cannot overlap. Quotation limit: 320 characters; above 160 characters the editor warns and the public display uses the safe page flow below the hero.

All 52 consecutive weeks, starting Monday 5 October 2026, contain the exact church-approved wording and are published. Week 1 retains Susan’s supplied 1 Peter 5:7 quotation with NLT metadata. Weeks 2–52 use `Website paraphrase` in the existing translation field and an explanatory internal note: these are approved summaries, not verbatim NLT. Week 46 is Psalm 56:3; 1 John 1:5 appears only in Week 2. To replace a summary with approved verbatim NLT wording, edit the quotation and change translation to NLT. The public reference and Admin preview reflect that metadata without changing the content schema or scheduling mechanism.

`build-homepage-verses.js` validates the source and generates `homepage-verses.json` containing only published entries, without internal notes or metadata, plus the shared browser model. The Dev content workflow runs this after each Admin save. Once future verses are published and deployed, client selection requires no subsequent weekly commit/deployment. Europe/London local dates and Monday–Sunday inclusive boundaries determine exactly one verse. Open tabs reselect each minute and refresh the schedule every 15 minutes or on return to the tab. Missing, malformed, conflicting or unavailable data hides the feature without fallback text.

At widths of 1000px and above, short quotations sit directly over the left sky, with cream text, a restrained text shadow and a small gold reference. Narrow screens and longer quotations display in normal page flow just after the frozen hero, on the existing page surface. No image treatment, overlay, animation or welcome-block movement is introduced. The homepage footer links to `bible-translation.html` for the NLT acknowledgement and publisher guidance.

The dedicated GET/PUT `/api/homepage-verses` endpoint uses the existing Easy Auth perimeter and verified-claim server allowlist. The GitHub App can read/write only the handler’s fixed `micklehamchurch/website`, `Dev`, `_content/homepage-verses.json` target. Neither query parameters nor body selectors can change the target. Writes validate a bounded JSON stream and atomically include the current blob SHA. Browser tokens stay in the existing MSAL closure; there is no generic writer or browser GitHub credential. The source repository is public: internal notes are omitted from the public display schedule, but must not contain secrets.

Validation: `node --test test/homepage-verses.test.cjs azure-function/test/homepage-verses.test.js`; production build: `npm run build`. Browser checks: `scripts/check-homepage-verses.cjs` with an installed Playwright module (`PLAYWRIGHT_MODULE` optionally sets its location). `VERSES_BASE_URL` switches the public checks to a deployed site. Browser Admin editing tests use a mock API; they do not weaken or replace live authentication.
